# 加仓预览器功能设计文档（Web 端）

## 一、功能概述

Web 端「加仓」弹窗原有的操作预览只有 5 个字段（买入净值、买入金额、新增份额、持有份额、成本价、持有成本），
无法回答用户最关心的问题：**"我亏了 30%，加仓 1 万能把收益率拉回到多少？"**

本功能在加仓弹窗预览下方新增入口按钮，跳转到一个独立的**加仓预览页**：

- 展示加仓后**所有会变化的字段**（收益、收益率、仓位、回本距离、组合影响等，均为 `加仓前 → 加仓后` 对照）
- 提供**快捷加仓金额档位**（500 / 1k / 2k / 3k / 5k / 1w / 2w / 5w，以及半仓 / 等额 / 双倍），点击即时重算
- 顶部可**切换基金**（按钮 / 键盘 / 移动端滑动），排版与手势对齐「基金详情页」
- 底部**确认加仓**，二次确认后写入持仓（仅本地，不自动云同步）

> 仅 Web 端实现，VSCode webview 端保持不变。

## 三、计算模型

### 3.1 公式

```
新增份额 addShares = amount / buyNav
新份额   newNum    = num + addShares
新成本价 newCost   = (cost × num + amount) / newNum
```

加仓前后指标**全部复用 `buildFundRowDisplay()`** 计算（仅替换 `fund` 对象的 `num` / `cost`），
保证预览页数字与首页列表逐位一致。

派生指标：

```
回本还需涨 breakEvenRisePct = (cost / 最新净值 − 1) × 100    // ≤ 0 显示「已回本」
持有仓位   positionPct       = 持有市值 / 组合总资产 × 100    // 加仓后分母 + amount
```

### 3.2 变化字段清单

| 字段 | 取值口径 | 加仓后是否变化 |
|---|---|---|
| 持有份额 | `fund.num` | ✅ |
| 成本价 | `fund.cost` | ✅ |
| 持有成本 | `num × cost` | ✅ |
| 持有市值 | `num × 单位净值` | ✅ |
| 持有收益 | `持有市值 − 持有成本` | ✅（买入净值 ≠ 当前净值时） |
| 总收益率 | `持有收益 / 持有成本` | ✅ |
| 估算收益 | `buildFundRowDisplay().estimatedGain` | ✅（随份额等比） |
| 当日收益 | `buildFundRowDisplay().dailyGain` | ✅（随份额等比） |
| 持有仓位 | `持有市值 / 组合总资产` | ✅ |
| 回本还需涨 | `成本价 / 净值 − 1` | ✅ |
| 当日涨幅 / 估算涨幅 / 单位净值 / 估算净值 / 净值日期 / 关联板块 / 更新时间 | — | ❌（单列展示，说明"为什么没变"） |
| 组合：总资产 / 总持有收益 / 组合收益率 / 平均收益率 / 总当日收益 | 复用 `calc.ts` 现有纯函数 | ✅ |

### 3.3 验算示例

份额 1,000、成本价 1.9739、最新净值 1.3817（当前 −30.00%），加仓 10,000 元 @1.3817：

| 项目 | 加仓前 | 加仓后 |
|---|---|---|
| 持有份额 | 1,000.00 | 8,237.46 |
| 成本价 | 1.9739 | 1.4536 |
| 总收益率 | −30.00% | **−4.95%**（+25.06pp） |
| 回本还需涨 | +42.86% | **+5.20%** |

## 四、交互设计

### 4.1 快捷金额与手动输入

- 金额输入使用 `el-input-number`（`step=100`，左右两侧各有 −/+ 按钮，`min=0`），支持任意金额手输
- 固定档位：`500 / 1k / 2k / 3k / 5k / 1w / 2w / 5w`
- 比例档位：`半仓 / 等额 / 双倍`（按加仓前持有市值计算，持仓为 0 时隐藏）
- 点击档位 → 纯前端重算（**不发请求、无 loading**），结论卡做一次高亮闪动提示"已刷新"
- 当前金额与档位一致时档位高亮；移动端自动把高亮档位滚动到可视区中间
- 金额记忆：`localStorage.fund_helper_last_add_amount`，下次进入自动带出

### 4.1.1 「pp」说明

变化量列中所有百分比差值都带 `pp` 单位（percentage point，百分点），这些数值：

- 带**虚线下划线**（可 hover 的视觉提示）
- 包在 `el-tooltip` 里，`#content` 按**当前行的真实数据逐行**生成，例如：

  ```
  pp = 百分点（percentage point），两个百分比相减的单位
  总收益率：-30.00% → -4.95%
  变化量 = -4.95% − (-30.00%) = +25.05pp
  即提升了 25.05 个百分点，不是上涨 25.05%
  ```

- **数值自洽**：变化量统一用 `pctDelta() = round2(加仓后) − round2(加仓前)` 计算，
  即"等号两边"与页面上展示的百分比完全一致（此前用原始值相减会出现 25.06 vs 25.05 的 0.01 误差）
- 「持仓变化」标题旁的 ⓘ 用三行说明整张表：左侧加仓前、右侧加仓后、最右列为变化量（金额为差值、百分比为 pp）
- tooltip 内容为多行 DOM（`.pp-tip`，`max-width: 280px`、`line-height: 1.7`），不是单行拼接文本

### 4.2 手势与快捷键（对齐基金详情页）

| 操作 | 行为 |
|---|---|
| 移动端左右滑动 | 切换上一支 / 下一支基金（阈值 50px 或 0.3px/ms，首尾循环；金额条与输入框区域不触发） |
| `W/S`、`↑/↓`、`A/D`、`←/→` | 切换基金（触底回首） |
| `1` ~ `8` | 选择第 N 个快捷金额档位 |
| `Enter` | 打开确认加仓弹窗 |
| `Esc` | 返回列表 |
| 输入框聚焦时 | 所有快捷键不生效 |

### 4.3 确认加仓

1. 点击底部「确认加仓」→ `ElMessageBox` 二次确认（净值、金额、新增份额、加仓后份额 / 成本价 / 收益率）
2. 确认后调用 `fundService.updateFund(code, newNum, newCost, groupKey)`
3. 成功后 toast 提示并返回首页（首页路由守卫会自动刷新数据）
4. 仅写入本地存储，**不自动云同步**

> 注意：`ElMessageBox` 使用 `autofocus: false`，并在打开前让出一次宏任务。
> 否则通过 `Enter` 快捷键打开弹窗时，键盘的默认行为会立刻点中刚挂载的「确认加仓」按钮，
> 等于跳过二次确认直接写入持仓。

### 4.4 隐私 / 灰阶模式

- **隐私模式：本页不生效**。加仓预览是"决策页"，隐藏金额就失去了意义，因此页面内所有金额、份额
  始终显示真实值（不调用 `formatPrivacy`，也不渲染 `.privacy-value` 遮罩）
- 灰阶模式：`.positive/.negative` 取 `var(--color-up/down)`，由 `[data-grayscale]` 自动降级为同一颜色

## 六、边界情况

| 情况 | 处理 |
|---|---|
| 基金不在持仓列表 | 空态提示 + 返回按钮 |
| 基金详情缺失 | 自动 `fetchFundDetail()` 补拉一次；仍失败显示"正在获取" |
| 净值 ≤ 0 | 空态提示 + 刷新按钮，禁用确认 |
| 金额 ≤ 0 | 结论区为空、确认按钮禁用 |
| 加仓金额过大 / 份额 NaN | 写入前 `Number.isFinite` 校验 |
| 重复点击确认 | 按钮 loading + 禁用 |
| 未填金额就点入口 | 跳转后使用"上次金额"或默认 1000 |
| 买入净值来源 | 来源基金沿用弹窗所选净值；切换基金后用该基金最新单位净值 |
